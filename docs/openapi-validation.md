# Перевірка OpenAPI та знімки екрана для частини 2

## Результат перевірки

24 листопада 2026 року специфікацію `openapi.yaml` версії `0.2.0` перевірено локальним Redocly CLI `2.83.0` із рекомендованим набором правил (`redocly.yaml`). Контракт містить 4 шляхи та 8 операцій: 5 операцій керування посиланнями, GET і HEAD для переходів та GET для health check.

```powershell
npm ci
npm run lint:api
# Команда з методички з використанням уже встановленої версії:
npx --no-install @redocly/cli lint openapi.yaml
```

Результат: exit code 0, 0 помилок, 4 попередження. Повний фактичний вивід збережено в [openapi-lint.txt](openapi-lint.txt). Попередження залишені видимими, правила не вимикалися.

| Правило | Місце | Причина залишення |
| --- | --- | --- |
| `info-license` | `info` | Власник не обрав ліцензію для проєкту; поле license не заповнюється вигаданою ліцензією. Це необов'язкове поле OpenAPI. |
| `operation-2xx-response` | `GET /r/{code}` | Правильний успішний результат цієї операції — перенаправлення 302. Відповідь 200 не виконує її призначення. |
| `operation-2xx-response` | `HEAD /r/{code}` | Повертає заголовки того самого перенаправлення 302 без тіла й без зміни лічильника. |
| `operation-4xx-response` | `GET /health` | Health check не має обов'язкового вводу: повертає 200 або 503. Додавання штучного 400 змінило б контракт частини 1 без потреби. |

Специфікація містить обов'язковість полів, типи, обмеження, requestBody, параметри, приклади, HTTP-коди, Location та Cache-Control. Повторювані схеми, заголовки, параметри й помилки винесені в components і підключені через `$ref`. Розділ info також описує загальні 404/405 і порядок перевірки запиту. `security: []` явно позначає відкритий навчальний API.

Окремо перевірено генерацію ініціалізатора Swagger UI на основі наявного `src/app.js`: об'єкт специфікації, переданий у SwaggerUIBundle, повністю збігається з розібраним кореневим YAML, має версію 0.2.0, 4 шляхи та 8 операцій. Для цієї перевірки HTTP-сервер і Docker-контейнери не запускалися; візуальну перевірку в браузері та скриншоти виконує користувач за кроками нижче.

Бізнес-маршрути на цьому етапі лише спроєктовані. Валідація OpenAPI підтверджує коректність опису, а не працездатність майбутньої реалізації. Підключення вже наявної Swagger UI залишено на `/docs/`; маршрутів CRUD або перенаправлення в частині 2 не додано. Внутрішній порт БД залишається 5432, зовнішній — 5435, як підтвердив користувач; локальний `.env` не змінювався.

## Знімок результату перевірки лінтером

1. Відкрийте PowerShell у корені репозиторію. Docker для цього знімка не потрібний.
2. Якщо залежності ще не встановлені на цьому комп'ютері, виконайте `npm ci`.
3. Розгорніть вікно термінала, збільште шрифт до читабельного та виконайте:

   ```powershell
   npx --no-install @redocly/cli --version
   npm run lint:api
   $LASTEXITCODE
   ```

4. Прокрутіть до кінця. На знімку мають бути видимі команда, назва `openapi.yaml`, підсумок `Your API description is valid`, `4 warnings` і код завершення `0`. Зробіть знімок через `Win + Shift + S`.
5. Для фіксації всіх попереджень зробіть додаткові знімки верхньої частини виводу з назвами правил і шляхами. Поруч у звіті вставте пояснення з таблиці вище. Самі попередження не слід приховувати або видавати за помилки.

## Знімок таблиці API

1. Відкрийте [api-design.md](api-design.md) у редакторі з Markdown preview або перенесіть таблиці до фінального звіту.
2. Для знімка використайте розділ «Операції та відповіді». Якщо таблиця не вміщується на екран, зробіть кілька послідовних знімків із видимими заголовками стовпців; не зменшуйте шрифт до нечитабельного.
3. Перевірте, що видно всі 6 обов'язкових дій із методички та додаткові HEAD і health check. У текстовій частині звіту залиште також таблицю полів і обґрунтування рішень, а не лише знімок.

## Знімки Swagger UI на окремій адресі

1. Переконайтеся, що Docker Desktop працює. Базу не потрібно зупиняти або перестворювати. Для оновлення копії YAML в образі та запуску сервера виконайте:

   ```powershell
   docker compose up --build -d --wait server
   docker compose ps
   ```

   Простий `docker compose start server` запустить старий образ із попередньою специфікацією. Параметри підключення Compose бере з `.env`; перевірена конфігурація — `db:5432` усередині мережі та `127.0.0.1:5435` із комп'ютера.

2. Відкрийте в браузері <http://localhost:8080/docs/> (або підставте PORT зі свого `.env`). Якщо сторінка була відкрита раніше, натисніть `Ctrl + F5`.
3. Переконайтеся, що видно назву `URL Shortener API`, версію `0.2.0` і групи `Links`, `Redirects`, `Infrastructure`. Залиште адресний рядок браузера видимим і зробіть загальний знімок: він підтверджує окрему адресу `/docs/`.
4. Розгорніть `POST /api/links`. Зробіть знімок request body з полями originalUrl та alias; за потреби ще один — блоку Responses із 201, 400, 409, 413, 415, 500, 503 та заголовком Location для 201.
5. Розгорніть `GET /api/links` і зафіксуйте limit/offset та схему LinkList. У Schemas розгорніть Link, щоб було видно code, originalUrl, shortUrl, createdAt, clicks і їхні типи.
6. Розгорніть `GET /r/{code}`, покажіть відповідь 302 та заголовки Location і Cache-Control. Окремо можна зафіксувати HEAD, який не змінює clicks.
7. На цьому етапі не виконуйте бізнес-запити через Try it out: їхні маршрути реалізуються в частині 3. Не додавайте очікувані відповіді зі Swagger до test.txt як нібито отримані результати. Функціональні знімки кожної операції та кожного коду стану належать до частини 3.
8. Після перегляду поверніть попередній стан сервера, залишивши базу працювати:

   ```powershell
   docker compose stop server
   docker compose ps -a
   ```

## Матеріали для фінального звіту

До розділу частини 2 включіть таблиці та обґрунтування з `api-design.md`, повний актуальний текст кореневого `openapi.yaml`, результат лінтера, пояснення чотирьох попереджень і власноруч зроблені знімки. Кореневий YAML залишається єдиним джерелом специфікації; окрему другу копію YAML у репозиторії не створено.

Порядок двох комітів видно командою `git log -2 --oneline`: спочатку таблиця API й рішення, потім OpenAPI та перевірка. Push на цьому етапі не виконується.
