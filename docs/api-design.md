# Проєктування API сервісу скорочення посилань

Цей файл зберігає початкові рішення частини 2 (OpenAPI 0.2.0) для звіту. У частині 3 на пряму вимогу користувача змінено генератор на Base62 та додано повторне використання URL із відповіддю POST 200. Чинний контракт — кореневий `openapi.yaml` 0.3.0; актуальні пояснення й перелік змін — у [part3-implementation.md](part3-implementation.md).

## Частина 2 Крок 1 Таблиця API

Контракт визначає керування посиланнями через `/api/links`, переходи через `/r/{code}` та перевірку готовності через `/health`. Swagger UI доступний окремо за `/docs/` і читає кореневий `openapi.yaml`. Це матеріал для розділу звіту про частину 2; бізнес-маршрути реалізуються лише після коміту специфікації, у частині 3.

### Операції та відповіді

Усі поля JSON нижче обов'язкові, якщо прямо не зазначено інше. Тіла запитів мають тип `application/json` (дозволено `charset=utf-8`), максимум 16 KiB (16384 байти). Для POST і PATCH порожнє тіло, некоректний JSON або невідповідність схемі дають 400; відсутній чи непідтримуваний Content-Type — 415; завелике тіло — 413. Стиснені тіла запитів не підтримуються і дають 415. Перевірка типу/кодування передує читанню тіла; далі перевіряються розмір, JSON, параметри та бізнес-правила, потім виконується SQL.

| Дія | Метод і шлях | Параметри та тіло | Успішна відповідь | Помилкові відповіді |
| --- | --- | --- | --- | --- |
| Створити посилання | `POST /api/links` | Тіло `CreateLink`: `originalUrl: string`, необов'язковий `alias: string` | `201`, JSON `Link`; `Location: /api/links/{code}` | `400` некоректні дані; `409` alias зайнятий; `413` завелике тіло; `415` тип чи кодування тіла не підтримується; `500` внутрішня помилка; `503` база недоступна |
| Отримати перелік | `GET /api/links` | Необов'язкові query `limit: integer` (1–100, типово 20), `offset: integer` (0–2147483647, типово 0) | `200`, JSON `LinkList`, зокрема порожній список | `400` некоректний query; `500`; `503` |
| Отримати одне посилання | `GET /api/links/{code}` | Обов'язковий path `code: string` | `200`, JSON `Link`, лічильник не змінюється | `400` некоректний code/query; `404` код не знайдено; `500`; `503` |
| Змінити цільову адресу | `PATCH /api/links/{code}` | Обов'язковий path `code`; тіло `UpdateLink`: тільки `originalUrl: string` | `200`, JSON оновленого `Link`; code, createdAt і clicks зберігаються | `400`; `404`; `413`; `415`; `500`; `503` |
| Видалити посилання | `DELETE /api/links/{code}` | Обов'язковий path `code`, без тіла | `204`, без тіла | `400` некоректний code/query; `404` код не знайдено або вже видалено; `500`; `503` |
| Перейти на цільову адресу | `GET /r/{code}` | Обов'язковий path `code`, без тіла; query не підтримується | `302`, `Location` — оригінальна адреса, без тіла; clicks атомарно збільшується на 1 | `400`; `404`; `500`; `503`; при помилці перенаправлення немає |
| Перевірити адресу без переходу | `HEAD /r/{code}` | Той самий path `code`, query не підтримується | `302`, ті самі `Location` і `Cache-Control`, без тіла; clicks не змінюється | `400`, `404`, `500`, `503`, усі без тіла за семантикою HEAD |
| Перевірити готовність | `GET /health` | Без параметрів і тіла | `200`, JSON `HealthUp` | `503`, JSON `HealthDown`, якщо `SELECT 1` не пройшов |

Відповіді `/api/links` і `/r/{code}`, включно з помилками, мають `Cache-Control: no-store`; `/health` також має цей заголовок. JSON-відповіді мають `Content-Type: application/json` із допустимим параметром charset. `204`, `302` і всі відповіді на HEAD не містять тіла. Транспортні заголовки на кшталт Date та Connection не є полями прикладного контракту.

### Схеми даних

| Схема | Поле | Тип і обов'язковість | Обмеження та значення |
| --- | --- | --- | --- |
| `CreateLink` | `originalUrl` | string, обов'язкове | Абсолютний HTTP/HTTPS URL, від 1 до 2048 символів; правила нижче |
| `CreateLink` | `alias` | string, необов'язкове | 4–32 символи, `^[A-Za-z0-9_-]{4,32}$`; null і порожній рядок заборонені |
| `UpdateLink` | `originalUrl` | string, обов'язкове | Ті самі правила, що при створенні; інших полів немає |
| `Link` | `code` | string, обов'язкове, readOnly | 4–32 символи, той самий формат, що alias; зберігається регістр |
| `Link` | `originalUrl` | string URI, обов'язкове, readOnly | Нормалізована сервером цільова адреса |
| `Link` | `shortUrl` | string URI, обов'язкове, readOnly | Абсолютна адреса `{PUBLIC_BASE_URL}/r/{code}` |
| `Link` | `createdAt` | string date-time, обов'язкове, readOnly | RFC 3339 у UTC, наприклад `2026-11-24T12:00:00.000Z` |
| `Link` | `clicks` | string, обов'язкове, readOnly | Десяткове невід'ємне число, `^(0\|[1-9][0-9]*)$`, типово `"0"`; рядок зберігає точність PostgreSQL BIGINT |
| `LinkList` | `items` | array of Link, обов'язкове | Від 0 до limit елементів; порядок `created_at DESC, id DESC` |
| `LinkList` | `limit` | integer, обов'язкове | Фактичне значення 1–100 |
| `LinkList` | `offset` | integer, обов'язкове | Фактичне значення 0–2147483647 |
| `LinkList` | `total` | string, обов'язкове | Кількість усіх записів до limit/offset у тому самому знімку БД; десятковий рядок, як clicks |
| `Error` | `error` | object, обов'язкове | Тільки `code: string` і `message: string`, обидва обов'язкові |
| `HealthUp` | `status`, `database` | string, обов'язкові | Тільки `"ok"`, `"up"` відповідно |
| `HealthDown` | `status`, `database` | string, обов'язкові | Тільки `"error"`, `"down"` відповідно |

Об'єкти схем мають `additionalProperties: false`. Вхідні поля `code`, `shortUrl`, `createdAt`, `clicks`, `id` та будь-які інші невідомі поля відхиляються з 400. `id` є лише внутрішнім ключем БД і не передається клієнту. Клієнт може запропонувати code тільки через alias при створенні; після створення код незмінний.

Path `code` перевіряється після URL-декодування. Коректний за форматом, але відсутній код дає 404, а некоректний формат — 400. Query-параметри дозволені тільки для списку: кожен не більше одного разу, без масивів і вкладених об'єктів. Значення — десятковий запис без знака, пробілів, дробової частини та зайвих початкових нулів (`0` дозволено для offset). Невідомий або повторний параметр дає 400. Offset за межами списку дає 200 із порожнім items. `/health` зберігає просту поведінку частини 1: додатковий query ігнорується.

### Єдина структура помилок

```json
{
  "error": {
    "code": "ALIAS_CONFLICT",
    "message": "The requested alias is already in use."
  }
}
```

| HTTP | error.code | Умова |
| --- | --- | --- |
| 400 | `BAD_REQUEST` | Некоректний JSON, параметр або поле, відсутній originalUrl, неприпустимий URL/alias |
| 404 | `NOT_FOUND` | Посилання не існує; невідомий шлях поза документацією також повертає цей формат |
| 405 | `METHOD_NOT_ALLOWED` | Непідтримуваний метод на відомому шляху; відповідь також містить Allow |
| 409 | `ALIAS_CONFLICT` | Валідний alias уже зайнятий, зокрема під час конкурентних запитів |
| 413 | `PAYLOAD_TOO_LARGE` | Тіло POST/PATCH перевищує 16384 байти |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Тіло POST/PATCH має непідтримуваний або відсутній Content-Type чи Content-Encoding, відмінний від identity |
| 500 | `INTERNAL_ERROR` | Неочікувана помилка сервера/SQL; також вичерпано 5 спроб генерації унікального коду |
| 503 | `SERVICE_UNAVAILABLE` | Немає підключення до PostgreSQL або сплив тайм-аут доступу до нього |

`message` — непорожній читабельний текст; клієнт спирається на HTTP і `error.code`, а не на точне формулювання. SQL, пароль і stack trace у відповіді не розкриваються. `/health` зберігає спеціальну схему частини 1; HEAD за правилами HTTP не повертає JSON навіть при помилці. `405` — загальна відповідь на інший HTTP-метод, а не результат виконання однієї з підтримуваних операцій; вона описується в загальному контракті, а не додається до кожної операції штучно.

### Обґрунтування шляхів і методів

`links` — множина ресурсів, `code` — публічний ідентифікатор. Префікс `/api` відокремлює JSON API від документації, а `/r` відокремлює переходи від керування. Навіть alias `docs` не конфліктує з `/docs/`, бо його адреса — `/r/docs`. Варіант `/{code}` коротший, але потребує резервування службових назв; для цієї роботи обрано явні простори шляхів.

POST створює ресурс і повертає 201 з його представленням. Location указує саме на ресурс метаданих `/api/links/{code}`, а коротка адреса міститься в shortUrl. Перелік і метадані читаються GET без зміни clicks. PATCH змінює лише originalUrl; PUT вимагав би семантики повної заміни представлення з незмінними серверними полями. DELETE повертає 204 без JSON; повторне видалення дає 404, хоча кінцевий стан залишається тим самим.

Перехід використовує 302, бо ціль можна змінити через PATCH. На відміну від постійного 301, це не заявляє про незмінність адреси; `Cache-Control: no-store` додатково забороняє зберігання відповіді сумісним кешем. Обрано 302 замість 307, оскільки маршрут призначений тільки для GET/HEAD і збереження інших методів не потрібне. Лічильник збільшується атомарним SQL `UPDATE ... RETURNING` до надсилання Location; невдала операція БД не спричиняє редирект. Це кількість успішно оброблених сервером GET-запитів, включно з ботами та повторними запитами, а не унікальних людей чи гарантованих завантажень цілі. Підрахунок є побічною статистикою GET; клієнт не замовляє окрему зміну ресурсу. Для HEAD потрібна окрема обробка до GET, щоб автоматична поведінка Express не збільшувала лічильник.

### Правила адрес і кодів

Приймається абсолютний URI з `http://` або `https://`, непорожнім hostname, без username/password, необроблених пробілів, керувальних символів і зворотної косої риски. Вхід має бути коректним URI; додатково перевіряється через WHATWG `URL`. Після нормалізації `new URL(value).href` адреса також не повинна перевищувати 2048 символів. Fragment і query цільового URL дозволені; localhost та IP-адреси дозволені. DNS і доступність цілі не перевіряються, сервер не завантажує її вміст. Це дає відтворювану перевірку без зовнішніх мережевих запитів. Наприклад, `https://example.org` зберігається як `https://example.org/`. Схеми javascript, data, ftp і відносні адреси відхиляються. Ліміт 2048 — рішення проєкту, а не загальна межа стандарту URL.

Alias регістрозалежний: `Docs` і `docs` — різні коди. Автоматичний код має 8 символів із того самого алфавіту, генерується криптографічно випадково (`crypto.randomBytes(6).toString('base64url')`). Обмеження UNIQUE в PostgreSQL є остаточним захистом від колізій, включно з конкурентними запитами. Для випадкового коду виконується до 5 спроб, після чого — 500; для явного alias повторної генерації немає, конфлікт дає 409. Невалідний alias дає 400, бо запит некоректний незалежно від наявних даних, а 409 стосується стану вже наявних ресурсів.

Повторний POST з тією самою довгою адресою та без alias створює інший ресурс зі своїм code і clicks. Автоматичне об'єднання дублікатів позбавило б клієнта незалежних лічильників; у цій роботі воно не застосовується. Повторний POST із тим самим alias дає 409 навіть для тієї самої адреси. PATCH на ту саму адресу дозволений і повертає 200, зберігаючи решту полів.

Абсолютний shortUrl формується з налаштованого `PUBLIC_BASE_URL` без кінцевої косої риски, типово `http://localhost:8080`, а не з неперевіреного заголовка Host. Цей параметр підключається до реалізації в частині 3. BIGINT-лічильники clicks і total передаються десятковими рядками, щоб клієнти JavaScript не втрачали точність за межами Number.MAX_SAFE_INTEGER. Пагінація limit/offset проста для лабораторної та дозволяє послідовно отримати всі записи; стабільний додатковий порядок за id усуває неоднозначність однакових timestamp. Зміни між сторінками можуть зрушити offset; для великого сервісу доцільна курсорна пагінація. Items і total одного запиту читаються з одного знімка БД.

### Службові шляхи та межі реалізації

Swagger UI — HTML-сторінка `/docs/` з власними статичними ресурсами, а не бізнес-операція JSON API. Вона читає той самий openapi.yaml; специфікація не дублюється в JS. Окремий маршрут завантаження YAML не потрібний для показу Swagger UI і на цьому етапі не додається. Після зміни специфікації потрібне повторне збирання образу, оскільки Dockerfile копіює її під час build.

Відомі бізнес-шляхи дозволяють: `/api/links` — GET, POST; `/api/links/{code}` — GET, PATCH, DELETE; `/r/{code}` — GET, HEAD. Інші методи дають 405 із відповідним Allow; `/health` зберігає наявну поведінку Express частини 1. Запити GET/HEAD/DELETE не потребують тіла, тіло не використовується. Невідомі шляхи дають 404. Службові механізми HTML-документації та автоматичні технічні HEAD/OPTIONS Express поза бізнес-маршрутами не є CRUD-операціями.

Автентифікація не входить у завдання: всі операції відкриті, `security: []` оголошується явно. Це локальний навчальний сервіс без моделі власників посилань. Вибір прав доступу для публічного розгортання потребуватиме окремого проєктування.

### Джерела для обґрунтування

Структуру схем і компонентів визначено за [OpenAPI 3.0.3](https://spec.openapis.org/oas/v3.0.3.html). Семантику методів, Location, HEAD і статусів — за [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html); керування кешуванням — за [RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html). Для перевірки використовується [Redocly CLI lint](https://redocly.com/docs/cli/commands/lint), а правила щодо 2xx/4xx трактуються з урахуванням призначення health check і перенаправлення.
